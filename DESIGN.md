# recall design

recall is a small app with a pure, heavily tested core, a thin React shell and no server.

## Architecture

`src/domain` (SM-2, session state machine, statistics, day arithmetic) and `src/io` (Markdown/CSV
parsers, backup validation) are pure TypeScript with no React, DOM, clock or storage imports.
`src/storage` hides IndexedDB behind a `Repository` interface. `src/state/store.tsx` is the only place
that combines the two: it reads the clock, calls the pure scheduler, writes through the repository and
then updates a `useReducer` mirror. Components read the mirror and call store actions.

## Key decisions and trade-offs

| Decision                                                                                                                                                            | Why                                                                                                                                                                                                                                                                                                                                                                    | Cost / alternative considered                                                                                                                                                                                                                                                            |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **SM-2** as the scheduler                                                                                                                                           | About 100 lines with comments; the algorithm has decades of use (SuperMemo 2, early Anki).                                                                                                                                                                                                                                                                             | FSRS schedules better (fewer reviews for the same retention) but needs per-user fitted parameters and more state. The `review(schedule, grade, today)` seam allows swapping later.                                                                                                       |
| Interval grows by the EF **after** the answer                                                                                                                       | With the pre-answer EF, Hard/Good/Easy give identical next intervals, so the buttons look broken.                                                                                                                                                                                                                                                                      | A documented deviation from the literal SM-2 text. Tests pin both the formula and the invariants.                                                                                                                                                                                        |
| Four buttons mapped to SM-2 quality 1/3/4/5                                                                                                                         | Six-point scales are hard to use quickly; four is the Anki convention.                                                                                                                                                                                                                                                                                                 | Loses SM-2's distinction between quality 0, 1 and 2 (all "forgot").                                                                                                                                                                                                                      |
| Whole **local days** (`DayNumber`) instead of timestamps                                                                                                            | "Due tomorrow" should follow the wall clock; integers make forecasts an array index.                                                                                                                                                                                                                                                                                   | Travelling across time zones can shift a due date by a day; acceptable for flashcards.                                                                                                                                                                                                   |
| Only **Again** is re-queued in the session                                                                                                                          | Failed cards return before the session ends; Hard records successful recall.                                                                                                                                                                                                                                                                                           | This app's simplification, not SM-2: step 7 repeats every item scored below quality 4, which would include Hard (q = 3). Repeats create extra review logs; statistics count them (honest, if slightly inflated).                                                                         |
| Same-day repeats of a failed card leave EF unchanged                                                                                                                | Otherwise three Agains in one session take EF from 2.5 to the 1.3 floor ("ease hell").                                                                                                                                                                                                                                                                                 | This app's rule, inspired by SM-2 step 6 ("without changing the E-Factor"), which the paper states for any failure, not for same-day repeats. Passing the repeat (even with Easy) does not raise EF either; one rule (`repetitions === 0 && lastReviewedDay === today`) is easy to test. |
| **IndexedDB via `idb`** behind a `Repository` interface                                                                                                             | Async, transactional, no 5 MB string-only limit like `localStorage`; `idb` is a tiny promise wrapper.                                                                                                                                                                                                                                                                  | Dexie offers live queries and nicer migrations but is a bigger dependency than this schema needs.                                                                                                                                                                                        |
| Write to storage **before** dispatching                                                                                                                             | The UI never shows a change that failed to persist.                                                                                                                                                                                                                                                                                                                    | Slightly slower perceived response than optimistic updates; imperceptible for local IndexedDB.                                                                                                                                                                                           |
| **Read-modify-write inside the transaction** (`recordReview(cardId, build)`, `updateCard(cardId, update)`, the deck check in `saveCards`) plus a `BroadcastChannel` | Every tab (and the installed app window) keeps its own mirror. Building the new card from the stored one means a stale tab cannot roll back a schedule; a grade of a card another tab already passed today is refused (`StaleReviewError`) and the review screen drops it; cards cannot be added to a deck another tab deleted; the broadcast makes other tabs reload. | Deck renames are still last-write-wins, and two tabs opened at the same instant on first run could both seed the samples. No cross-tab locking.                                                                                                                                          |
| **Today is state** (`useToday`), not computed per render                                                                                                            | An installed PWA or a resumed phone tab stays open past midnight; the day must move on without a reload or the newly due cards stay hidden.                                                                                                                                                                                                                            | A timer for the next local midnight plus re-reads on `visibilitychange`, `focus`, `hashchange` and after each grade (timers are throttled in background tabs). A session already running keeps its queue; the summary offers the newly due cards.                                        |
| Whole dataset held in React state                                                                                                                                   | Simple selectors; a personal deck collection is thousands of cards at most.                                                                                                                                                                                                                                                                                            | Would need indexed queries and pagination for very large collections.                                                                                                                                                                                                                    |
| `useReducer` + context instead of Zustand/Redux                                                                                                                     | One store, a handful of actions, zero dependencies.                                                                                                                                                                                                                                                                                                                    | Every state change re-renders context consumers; fine at this size.                                                                                                                                                                                                                      |
| Tiny **hash router** instead of react-router                                                                                                                        | Five routes; hash URLs need no server rewrites on GitHub Pages or offline.                                                                                                                                                                                                                                                                                             | No nested routes, loaders or `history` URLs.                                                                                                                                                                                                                                             |
| `vite-plugin-pwa` (Workbox `generateSW`)                                                                                                                            | Correct precache manifest with content hashes, cache cleanup and update flow for free.                                                                                                                                                                                                                                                                                 | A hand-written service worker adds cache-management code and risks stale caches.                                                                                                                                                                                                         |
| Service-worker updates **prompt** instead of auto-reloading                                                                                                         | `autoUpdate` reloads every open tab when a new version activates, which can discard a half-typed card or a review queue.                                                                                                                                                                                                                                               | The user must click "Reload to update"; if they choose "Later", the old version runs until every tab is closed.                                                                                                                                                                          |
| Hand-rolled **SVG charts**                                                                                                                                          | Two single-series bar charts; full control over accessibility (role="img", table alternative).                                                                                                                                                                                                                                                                         | No zoom/pan or animated transitions; adding more chart types would cost more code.                                                                                                                                                                                                       |
| Answers rendered as **plain text** (`white-space: pre-wrap`)                                                                                                        | No HTML injection risk from imported files; Markdown code blocks stay readable.                                                                                                                                                                                                                                                                                        | No bold/links/syntax highlighting in answers. Rendering Markdown would need a sanitiser.                                                                                                                                                                                                 |
| Import shows a **preview** and imports only valid cards                                                                                                             | Imported notes may contain invalid headings; one bad heading should not block 40 valid cards.                                                                                                                                                                                                                                                                          | The user must read the problem list; nothing is imported silently.                                                                                                                                                                                                                       |
| **Lossless, safe export**: Markdown answer lines that look like headings get a `\` prefix; CSV cells starting with `= + - @` get a `'` prefix                       | Export → import returns the same cards (property tests), and a shared CSV cannot run formulas in Excel/Sheets (OWASP CSV injection).                                                                                                                                                                                                                                   | Other tools show the `\` or `'` literally; multi-line questions are joined into one line in Markdown.                                                                                                                                                                                    |
| CSV header aliases limited to front/back/question/answer                                                                                                            | One-letter aliases made a data row like `Q,A` look like a header.                                                                                                                                                                                                                                                                                                      | Files with other header names need renaming.                                                                                                                                                                                                                                             |
| Strict TypeScript (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`) and typescript-eslint strict-type-checked                                              | Catches undefined array access and sloppy optional props at compile time.                                                                                                                                                                                                                                                                                              | More explicit code (`?? 0`, `charAt`) in parsers.                                                                                                                                                                                                                                        |

## SM-2 deviations

`src/domain/sm2.ts` follows Wozniak's 1987 SM-2 description for the EF formula, the 1 → 6 → n×EF
intervals and the reset on failure. Where it differs, it is on purpose and tested:

1. **Interval uses the EF after the answer**, so Hard, Good and Easy give different next intervals.
2. **Same-day repeats of a failed card leave EF unchanged.** Inspired by step 6 ("without changing
   the E-Factor"), but the paper says that about any failure; the app still lowers EF on the first
   failure of the day, as most SM-2 implementations do.
3. **Only Again is re-queued** in the session. Step 7 repeats every item scored below quality 4,
   which would include Hard. With four buttons, Hard means "recalled with effort"; repeating it the
   same day would mostly add unnecessary reviews.

## Testing strategy

- **Unit (Vitest):** SM-2 examples plus fast-check properties; session reducer; statistics; parsers
  including a CSV round-trip property; backup validation; the reducer; routes.
- **Contract:** one suite runs against `MemoryRepository`, `IndexedDbRepository` (on
  `fake-indexeddb`) and the deferred wrapper, so the test double cannot drift from the real store.
- **Two tabs:** `store.test.tsx` mounts two `StoreProvider`s on one repository and checks that a
  stale tab's edit or grade keeps the other tab's review, that a second grade of a card already
  passed is refused, and that the change feed refreshes it. `ReviewSession.test.tsx` runs two review
  screens and checks a card graded in one tab leaves the other tab's queue.
- **Day rollover:** `useToday.test.ts` (fake timers across midnight, visibility and focus) and
  `DayRollover.test.tsx` (the app with a movable clock shows cards that fell due overnight).
- **Component (React Testing Library):** the whole app over an in-memory repository and a fixed
  clock; keyboard review flow, focus and live-region text, CRUD, import, stats, backup/restore.
- **End-to-end (Playwright):** against the production build served by `vite preview`, so the service
  worker and manifest are real. Covers import → review → reload persistence, leaving the review
  screen with Enter, offline grading that survives an offline reload, cross-tab refresh, backup
  download, the reveal animation with and without reduced motion, and axe-core WCAG 2.2 AA scans of
  seven screens in light and dark themes. `npm run smoke:base` checks a sub-path (GitHub Pages) build.

## Alternatives considered and rejected

- **Next.js / SSR:** nothing to render on a server; data is private to the browser.
- **A backend with accounts:** adds hosting cost, auth and privacy obligations; JSON backup covers
  moving data between devices.
- **Chart.js / Recharts:** a dependency larger than all the app code for two bar charts.
